# 答辩（A4 单页）· 基于 Python 的手机充电桌面监控系统

**答辩人：赵宇 | 指导教师：刘尚一 | 时长约 8–10 分钟**

---

## 30 秒开场
各位老师好。本系统是针对 Qi 无线充电的**桌面监控上位机**：串口采集电参 + 解析 Qi 2.2.1 报文 + 实时波形 + SQLite 落盘 + PDF 报告。定位是填补「手机 APP 看不见协议」与「专业仪器太贵」之间的空白。

---

## 系统功能（5 句话）
1. **采集**：UART 读 `AA55…EDED` 电参帧 + TX0 报文（`SerialWorker` 独立线程）
2. **展示**：PyQt5 界面 + PyQtGraph 四路曲线；报文悬停 tooltip 语义解析
3. **状态**：CC/CV/涓流识别 + **4 s 防抖**；满电须 **电量 100% + 20 s 去抖**
4. **安全**：OVP/OCP/OTP 可配阈值 → 日志 + 状态栏告警（满电单独弹窗）
5. **导出**：按 session 存 SQLite；CSV / PDF（符合性矩阵 + 波形 + 结论）

---

## 架构 & 数据流（必画白板）
**四层**：采集 → 处理/存储 → 预警旁路 → UI  
**三线程**：`SerialWorker` 读串口 | `DBWorker` 队列写库 | 主线程 UI 渲染（~100 ms）  
**通信**：Qt 信号槽 + `queue.Queue`；DB 用 **WAL + 批量 commit**

## 重难点 × 方案（PPT 第 15 页）
| 难点 | 方案 |
|------|------|
| GIL / 串口阻塞 UI | QThread 解耦 + signal/slot |
| 高频绘图内存涨 | PyQtGraph 更新数组，限制 500 点滑动窗口 |
| 海量 Qi 报文 | 字典查表 `Qi22Parser`，未知包写日志 |
| 充电状态抖动 | 40 点窗口 + 4 s 状态保持 |
| 高频写库 | SQLite WAL + 100 条/1 s 批量提交 |

## 高频提问 · 一句话答
| 问 | 答 |
|----|-----|
| 为何用 Python？ | I/O+GUI+报告生态全，开发快；重计算放子线程，满足监控场景 |
| 多线程怎么分？ | 采集/写库/界面三分；signal 传 dict，DB 用队列 |
| FSM 在哪？ | 充电：`ChargeStateTracker` 五态+防抖；安全：阈值+滞回+去重 |
| OVP 怎么告警？ | 超阈值→报文日志+状态栏红字；**非模态**（不挡监控） |
| 怎判充电完成？ | 涓流 + **SOC≥100%** + 稳定 20 s，否则显示「电量未满」 |
| PDF PASS 依据？ | 配置阈值符合性矩阵；**非型式认证**，需人工复核 |
| 演示模式？ | 无硬件模拟数据；报告自动 WARN |
| 0.5%/2 s/24 h 咋测？ | 对比表计算误差；时间戳差测延迟；长挂看内存/崩溃（**有数据报数，无则说明方法**） |
